## 1. 项目目标与范围

面向校园的二手物品信息平台：用户注册登录后可发布商品（名称、价格、联系方式），所有访问者可浏览、按名称模糊搜索、按价格排序；普通用户只能修改/删除自己的商品，管理员可修改/删除所有商品。项目以功能完整、分层清晰、便于 4 人协作为目标，不引入课程范围外的技术。

**本期功能（P0）**

1. 注册、登录、登出、获取当前登录用户信息。
2. 商品列表（分页）、按名称模糊搜索、按价格升/降序排序、商品详情。
3. 登录用户发布商品；普通用户修改/删除自己的商品；管理员修改/删除所有商品。
4. 后端 Session 认证、角色与归属校验、统一响应与错误处理。
5. 用户表 + 商品表、建表 SQL、README 与演示材料。

**本期不做（✅）**：即时聊天、在线支付、订单、收藏、评论、推荐、消息通知、商品图片上传、管理员用户管理（封禁/改角色）。

**暂不做（⏳ 可后续扩展）**：商品描述字段、个人信息修改、我的商品筛选、ECharts 统计、云部署。

## 2. 角色与权限

| 操作 | 游客 | 普通用户 USER | 管理员 ADMIN |
|---|---|---|---|
| 浏览列表、搜索、查看详情 | ✅ | ✅ | ✅ |
| 注册、登录 | ✅ | ✅（不改变登录态） | ✅（不改变登录态） |
| 获取当前用户、登出 | — | ✅ | ✅ |
| 发布商品 | — | ✅ | ✅ |
| 修改/删除自己的商品 | — | ✅ | ✅ |
| 修改/删除他人商品 | — | ❌ 403 | ✅ |

**强制规则**

1. 后端必须做认证与权限校验；前端隐藏按钮只用于体验，不作为安全边界。
2. 当前用户只从 Session 读取；请求体/参数中的 `userId` 一律忽略，不得作为权限依据。
3. 未登录返回 401；已登录无权限返回 403；商品不存在返回 404；不得用 200 掩盖失败。
4. 权限判定顺序：查商品（不存在 404）→ 管理员放行 → 本人放行 → 其他 403。

## 3. 功能需求

| 编号 | 功能 | 规则要点 | 验收要点 |
|---|---|---|---|
| F-01 | 用户注册 | 用户名 3–20 位字母/数字/下划线且唯一；密码 6–20 位；角色固定 USER；BCrypt 存储 | 注册后可登录；重复用户名 409；无明文密码 |
| F-02 | 用户登录 | 校验用户名/密码；成功建立 Session；失败统一提示「用户名或密码错误」 | 正确凭据可登录；错误凭据 401 |
| F-03 | 登出 | 使 Session 失效 | 登出后访问受保护接口 401 |
| F-04 | 当前用户 | 返回 `id`/`username`/`role` | 刷新页面可恢复登录态 |
| F-05 | 商品列表 | 分页展示；默认按创建时间倒序 | 空库返回空列表；分页正常 |
| F-06 | 搜索与排序 | `keyword` 模糊匹配商品名称，空关键词=全部；`sort=price_asc/price_desc` | 搜索结果与价格排序正确；非法参数 400 |
| F-07 | 商品详情 | 按 id 查询 | 不存在或已删除返回 404 |
| F-08 | 发布商品 | `item`、`itemPrice`、`contactInfo` 必填；归属取当前 Session | 发布后列表可见且 `userId` 正确 |
| F-09 | 修改商品 | 可改三个商品字段；仅本人或 ADMIN；`userId` 不可改 | 本人/管理员成功；他人 403；不存在 404 |
| F-10 | 删除商品 | 物理删除；仅本人或 ADMIN；前端二次确认 | 删除后详情 404；他人 403 |
| F-11 | 管理员管理 | 复用商品接口，可修改/删除所有商品 | 后端放行，前端显示操作入口 |

## 4. 业务规则与校验

- 用户名唯一、不区分大小写；注册角色固定 `USER`；登录失败不区分账号是否存在。
- 商品归属只由后端 Session 决定；商品删除为物理删除，不可恢复。
- 搜索：`item LIKE '%关键词%'`，关键词 trim 后为空等价于不筛选；排序默认 `created_at DESC, id DESC`，价格排序同价按 `id DESC`。
- 分页：`page ≥ 1`、`size ∈ [1,50]`，默认 `page=1,size=10`。
- 商品名称 1–100 字符；价格 > 0 且 ≤ 999999.99，最多两位小数；联系方式 1–100 字符。
- 所有字符串 trim 后校验/入库；时间格式 `yyyy-MM-dd HH:mm:ss`（Asia/Shanghai）；金额 JSON number。
- 管理员账号由 `sql/data.sql` 种子创建，注册接口不能创建管理员。

## 5. 数据字段

| 表 | 字段 | 说明 |
|---|---|---|
| user | `id`、`username`、`password_hash`、`role`、`created_at`、`updated_at` | 角色 USER/ADMIN；密码只存 BCrypt 哈希 |
| item | `id`、`item`、`item_price`、`contact_info`、`user_id`、`created_at`、`updated_at` | `user_id` 外键 → user.id，由后端 Session 写入 |

- API 与数据库字段映射：`itemPrice↔item_price`、`contactInfo↔contact_info`、`userId↔user_id`、`createdAt↔created_at`、`updatedAt↔updated_at`；`password` 只入不出。
- 表结构、约束与索引见 [database-design.md](database-design.md)。

## 6. 非功能要求（课程大作业标准）

- **安全（基础）**：BCrypt 密码、MyBatis 参数化查询、后端权限校验、仓库不提交密码/密钥；不做额外安全加固（CSRF、HTTPS、限流等不在本期范围）。
- **性能**：商品规模假设 ≤ 1 万条；列表必须分页（size ≤ 50）；本地接口响应 ≤ 500ms。
- **兼容**：JDK 21、MySQL 8.0.16+、Node.js 20+、Chrome/Edge 新版本；开发环境 Windows。
- **界面**：中文；有加载中/空数据/错误提示；删除前二次确认；列表卡片展示名称/价格/发布时间（联系方式在详情页），列表搜索/排序/分页状态同步 URL query。
- **部署**：本地演示；前端构建产物由后端单 Jar 同域提供。
